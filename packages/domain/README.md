# @goblins/domain

The shared data model: Drizzle schema, migrations, Effect schemas for the grade state machine, and the writes that more than one stream relies on.

## What's here

| File | Contents |
|---|---|
| `src/schema.ts` | Every table. Read its header comment first. |
| `src/grade.ts` | The grade state machine as an Effect Schema tagged union, the queue message (`GradeJob`) and what the pipeline reports (`GraderOutcome`) |
| `src/grades.ts` | All writes to `grades`: `startGrading` and `recordOutcome` for the pipeline; `acceptGrade`, `scoreGrade` and `retryGrade` for the teacher |
| `src/class-sessions.ts` | `joinSession` (join or resume by name) and `submitWork` |
| `src/names.ts`, `src/join-code.ts` | Name matching and join codes |
| `src/load-test.ts` | `deleteLoadTestRun` |
| `src/db.ts` | Layers: `DatabaseLive` (from `DATABASE_URL`) or `databaseLayer({ url })` |
| `migrations/` | Plain SQL generated by Drizzle Kit. Checked in. |

## Using it

```ts
import { DatabaseLive, Db, startGrading, recordOutcome } from "@goblins/domain"
import { schema } from "@goblins/domain"

const program = Effect.gen(function* () {
  const input = yield* startGrading(job) // Option: None means the message is stale, ack it
  // ...call the model...
  yield* recordOutcome(job, outcome) // "recorded" | "stale"
}).pipe(Effect.provide(DatabaseLive))
```

Build the Drizzle client with `DbLive` or `DatabaseLive`, never `PgDrizzle.layer` directly: columns are snake_case in Postgres and Drizzle only maps them when `casing: "snake_case"` is set.

## Grading idempotency

Queue delivery is at-least-once. Each grading attempt has a number; the queue message carries `{ submissionId, attempt }`, and every pipeline write is an UPDATE that matches the attempt and the expected state. So:

- A redelivered message after the result is written matches nothing and is acknowledged.
- A message for an attempt the teacher has since retried or scored is stale and dropped.
- A redelivery while the first delivery is still in flight can call the model twice; the first result wins. That costs one extra call in a rare case, and avoids a lease.

`submitWork` is idempotent per student and problem. While the grade is still `submitted` it returns the job again, so a client retry also re-enqueues a message that was lost after the first write. `pendingJobs(sessionId)` lists grades still waiting, for a sweeper.

## Load-test data

The app stamps `load_test_run_id` on the teacher, assignment and class session a load test creates. Students, submissions and grades belong to those by cascade. Real views filter `load_test_run_id is null`; `deleteLoadTestRun(runId)` deletes the whole run.

## Commands

```bash
pnpm --filter @goblins/domain test          # PGlite (real Postgres in WASM), no Docker needed
pnpm --filter @goblins/domain db:generate   # after editing schema.ts; commit the new migration
pnpm --filter @goblins/domain db:migrate    # apply to DATABASE_URL; runs on deploy
```
