# Security review

Reviewed 2026-10-15 against `main` at `6f4bab7`. The review was read-only. It covered every `/api` route, every server function, the shape proxy, the load-test and queue endpoints, setup, share links, environment configuration and dependencies. Against production (https://goblins-takehome-three.vercel.app and `goblins-electric.fly.dev`), it sent only a few unauthenticated GET and POST requests to check that each gate refuses. It did not sign in, join a session or create data.

No Critical findings. Two High findings, both about spending the model budget: one through setup, one through grading. Both went to the orchestrator as soon as they were found. Two Medium and nine Low findings follow.

## Verified safe

- **Teacher authorization.** Every teacher server function (`fns/sessions.ts`, `fns/grading.ts`, `report/fns.ts`) goes through `ownedSession`, which filters by `teacher_id`. `ownedSubmission` resolves the submission's session and then checks ownership. `renameStudent` and `splitStudent` scope by both `sessionId` and `studentId`. `/api/teacher/*` uses `teacherFor`, which falls back to Clerk, and also filters by `teacher_id`. Live: unauthenticated `POST /api/teacher/sessions` returns 401.
- **Setup ownership.** `ownedAssignment`/`owns` checks the teacher id or the random `gb_draft_owner` UUID cookie (HttpOnly, Lax, Secure in production). `launch` requires Clerk, and `claimDrafts` moves only the caller's own drafts.
- **Request isolation (#47).** `run` reads Clerk's `auth()` and the cookies at the handler boundary. Cookies are set after the effect resolves, and no effect calls `getCookie`, `auth` or `getRequest`. The join server function returns the signed cookie value only to its own handler.
- **Student cookie.** HMAC-SHA256 over `sessionId.studentId` with `STUDENT_COOKIE_SECRET`, compared with a length check and `timingSafeEqual`. The secret is set as a Production secret in Vercel; this review could not read its value to confirm it differs from the committed `local-development-only`. Submits check that the student belongs to the session and the problem to its assignment, and that the session is live.
- **`AUTH_MODE=local`.** `localTeacherMode` requires `VERCEL` to be unset, and `AUTH_MODE` is not set in any Vercel environment.
- **Shape proxy (#73, #104).** The browser sends only a view name and a session UUID. The server picks the table, `where`, params and columns, and `set` overwrites any client-sent `table`, `where`, `columns`, `params[n]` or `secret`. Teacher views require session ownership. Student views require a valid cookie for that session, and `my-session` omits `join_code`. The shared grades shape is filtered server side to the cookie's `student_id`, with `replica=full`, and anything other than a JSON array becomes `[]` or a 500. Responses get `cache-control: private, no-store` and `vary: cookie`. `ELECTRIC_SECRET` is added only to the upstream URL. Live: unauthenticated teacher view returns 401, student view without a cookie returns 403, and Electric on Fly without the secret returns 401.
- **Load-test endpoints.** `authorizeLoadTest` compares SHA-256 digests with `timingSafeEqual`, treats an unset or empty `LOAD_TEST_TOKEN` as "not a load test", and validates the run id. `/api/load-test/*` returns 403 without a valid token, verified live for `db`, `timings` and `cleanup`. `deleteLoadTestRun` deletes by `load_test_run_id = $runId` only, and the run id in the path must match the header, so it cannot reach rows where that column is null. Load-test grades always use the mock.
- **Queue and sweep.** `/api/queue/grade` verifies the QStash signature on the raw body before parsing (live: 401). `/api/grading/sweep` requires a QStash signature or `Bearer $CRON_SECRET` (live: 401).
- **Uploads and whiteboards.** Uploads must be JPEG, PNG or WebP by declared type, at most 10 pages and 4 MB, stored as `data:` URLs with that fixed type, so no SVG or HTML can be stored. Whiteboards must start with the PNG signature and are capped (3 MB / 4M base64 characters). Images render only through `<img src>`.
- **SSRF.** No user-supplied URL is ever fetched. Whiteboard and upload URLs are built by the server as `data:` URLs. Template page URLs come from the request origin, and Vercel routes by host. The mock's http(s) image fetch only sees those URLs.
- **XSS.** Names, problem text and chat replies render as React text. KaTeX 0.19.0 runs with `trust: false` (the default where not set), which emits no links or raw HTML, and `pnpm audit` reports no advisory for it.
- **Share links.** 128-bit `randomBytes` tokens, shape-checked before lookup, with "not found" identical for wrong and missing tokens. `anonymize` replaces names with "Student N", zeroes avatars and drops grader reasons on the server. The teacher's name and the problem text stay visible by design.
- **Secrets.** `git log -p --all` shows no OpenRouter, Clerk, Postgres, QStash or Blob secrets. The only committed env file, `apps/web/local.env`, holds local Docker defaults. The client uses only `VITE_CLERK_PUBLISHABLE_KEY`. `VITE_NEON_AUTH_URL` exists in Vercel but is never referenced, so Vite does not bundle it. `OPENROUTER_API_KEY`, `CLERK_SECRET_KEY`, `LOAD_TEST_TOKEN`, `STUDENT_COOKIE_SECRET`, `ELECTRIC_SECRET` and `CRON_SECRET` are Production-only and marked secret.
- **CSRF.** State-changing routes are POST. Clerk's session cookie and the app's cookies are `SameSite=Lax`, and `vercel.app` is on the Public Suffix List, so other Vercel sites are cross-site.

## Not verified

- Live behavior of authenticated or student flows: no sign-in or join against production, by instruction.
- Whether Electric 1.8.1 accepts `subset__where` filters on columns outside `columns` (finding 5).
- Fly organization membership and Neon role permissions: no dashboard access. `deploy.sh` stores `ELECTRIC_SECRET` as a Fly secret. Which Neon role Electric's `DATABASE_URL` uses was not checked; a read-only replication role would limit the damage if the Fly machine were compromised.
