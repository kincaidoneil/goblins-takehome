| 2026-10-15 | Repo | Layout: `apps/web` plus `packages/{domain,ui,grader,mock-model,templates,evals,simulator,loadtest}` | One package per stream, as the PRD asks; the mock model gets its own package so its stream can work in parallel with the pipeline |

| 2026-10-15 | Grader | `packages/grader` defines `ModelClient`, an Effect service whose one operation takes a model id and messages and returns the completion with usage and cost, or a typed error (rate limit, timeout, provider error, bad response). `packages/mock-model` provides a Layer for it | Lets the pipeline and mock streams start at once against one agreed interface; the grader stream may refine the shape in its first PR and tells the mock stream |
| 2026-10-15 | Secrets | Local secrets file is `.env.local` at the repo root | Read by Vite and the Vercel CLI by default |
| 2026-10-15 | Grader | `ModelClient.complete(request)` takes model, messages (text and image parts), a call tag (purpose, subject id, load-test run id) and optional max tokens, temperature and JSON schema; returns id, answering model, text and usage with provider-reported cost; errors are `RateLimited`, `Timeout`, `ProviderError`, `BadResponse`, with `isRetryable` | The tag carries what the call log needs without a second API; `purpose` maps onto the PRD's budget lines so the usage report can compare spend per line |
| 2026-10-15 | Grader | Effect 3 (`^3.22`), not Effect 4 | The PRD fixes `@effect/sql-drizzle`, whose latest release still requires Effect 3; every package should share one Effect major |
| 2026-10-15 | Mock model | The mock decides each call in two independent parts: scripted content from a marker in the request text, and a fate (latency and failure) from fixed, sampled, scenario or replay timing | Any timing source works with any script, so E2E tests, the load test and scenarios share one code path |
| 2026-10-15 | Mock model | E2E tests pick a grade state with a text marker such as `[[mock:needs-teacher reason="..."]]` in the request; a scripted failure can carry an `until` deadline | A whiteboard image can't carry a script, and a deadline lets a test see a failed grade succeed on retry without state shared across serverless instances. | 2026-10-15 | Mock model | Scenarios and replay are functions of time since a run start sent in the load-test header, not of in-memory counters | Grading runs on many function instances; a shared clock is the only state they all have |
| 2026-10-15 | Mock model | Scenario defaults: rate-limit storm rejects 70% of calls for minutes 2–5; provider down returns 503 for minutes 2–7; latency doubling applies to the whole run | Two clean minutes give each run a baseline to compare against; 5 minutes matches the PRD's outage criterion |
| 2026-10-15 | Mock model | Until real calls are logged, realistic mode uses a guessed seed profile (median 3.5 s, p95 9 s, about 1.2% errors) and a synthetic recording, both labelled as such in code and README | The PRD asks for sampling from logged calls; there are none yet, and the latency calibration budget has not been spent |
| 2026-10-15 | Mock model | Profiles and recordings ship as code in the package, exported from the call log, rather than read from the database at runtime | Every instance has them without a query, and a load-test run is reproducible from a commit |
| 2026-10-15 | Mock model | A load-test header selects the mock even in production and is not secret | The PRD wants anyone with the repo to re-run the load test; the header only changes data that is tagged as load-test data and deleted after the run. The web app must enforce that tagging |
| 2026-10-15 | Mock model | Mock calls report zero cost but realistic token counts | Usage reports stay true about spend, and token volumes still have a realistic shape |
